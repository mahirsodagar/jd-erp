# 6 — Teaching (LMS)

For faculty. Menu group: **LMS** — Assignments, Courseware, Lessons, Marks and
Tests.

---

## 6.1 Assignments

**LMS → Assignments.**

### Creating one

An assignment belongs to a **subject**, and you choose who gets it:

- **One batch** — only that batch sees it.
- **A whole program** — every batch in the program sees it.

You also set the title, description, maximum marks, due date, an optional
attachment (a brief, a template) and an optional cover image for the card.

**Publishing.** An assignment can be created unpublished — students see nothing
until you publish it. Use this to prepare work in advance.

### Students submitting

Students submit from their portal: a file, typed text, or both. Each student
has one submission per assignment; resubmitting replaces what was there.

Submissions are marked **Submitted** or **Late**, based on the deadline.

### Giving one student more time

You can set an **extended due date** on an individual student's submission.
Only that student's deadline moves; everyone else keeps the original.

### Grading

Open the assignment's submissions list, enter a mark and feedback. The
submission becomes **Graded**. If you want the work redone, set it to
**Resubmit** with feedback explaining why.

### Who can do what

- You can always create, edit and grade **your own** assignments.
- Editing, deleting or grading **someone else's** needs additional permissions.

Students receive an email when an assignment is set.

## 6.2 Courseware

**LMS → Courseware.**

Reference material for a subject, published to a batch: notes, slides,
references, sample work.

1. Create a **topic** — subject, batch, name, description and an optional cover
   image.
2. Attach **files** — as many as you need per topic.
3. **Publish** it. Every student with an active enrolment in that batch is
   given access.

> **Important.** Access is granted to the students who are in the batch **at
> the moment you publish**. A student who joins the batch afterwards will not
> see that topic. If students join mid-term, republish the topic so they get
> access.

Students find it under Course Ware in their portal.

## 6.3 Lesson plans

**LMS → Lessons.**

A lesson plan is your teaching plan for a batch — what will be covered, what
work is set, and when it is due. Unlike an assignment, the value is the plan
itself.

### What goes in one

| Field | Notes |
|---|---|
| **Batch** | |
| **Unit** | The topic or unit covered |
| **Assignment** | The work described in the plan |
| **Submission deadline** | Either a date, **or** a description such as "after the 4th session". At least one is required |
| **Module project** and its due date | |
| **Semester-end project** and its due date | |
| **Visits, workshops, seminars** | |
| **Display date** | Optional. Students only see the plan on or after this date |
| **Reviewers** | The HOD and the class mentor |

### Approval — both reviewers must agree

A lesson plan goes to **two** reviewers: the **HOD** and the **class mentor**.
Each independently records a decision and remarks:

| Each reviewer can say | |
|---|---|
| **Approved** | |
| **Rejected** | |
| **Needs improvement** | Sent back for changes |

The plan's overall state follows these rules:

- If **either** reviewer rejects it → **Rejected**.
- Only when **both** approve → **Approved**.
- If either asks for improvement (and nobody rejected) → **Needs improvement**.
- Otherwise → still awaiting review.

**Students only see the plan once both reviewers have approved it** — and, if
you set a display date, not before that date.

If it comes back as "Needs improvement", read both sets of remarks, revise, and
it goes round again.

## 6.4 Marks

**LMS → Marks.**

Marks are recorded per **student, subject and semester**, split into two parts:

- **Internal assessment** — out of 20 by default
- **External assessment** — out of 80 by default

Both maximums can be changed per entry. The total and percentage are worked out
for you.

### Draft, then publish

This is a **two-stage** process on purpose.

1. **Faculty enter marks.** They are drafts — students cannot see them.
2. **The HOD publishes them.** Only then do they appear in the student's
   transcript and portal.

Once published, editing needs a further permission. Publishing and retracting
("unpublish") are separate permissions again.

If you spot an error after publishing, either ask someone with the
edit-published permission to correct it, or have it retracted, corrected and
republished.

### Transcripts

A transcript pulls together a student's marks across subjects and semesters.

- Students see their own at **Academics → Records → My Transcript**, and in the
  portal.
- Staff need a permission to view any student's transcript.
- **Unpublished marks are left out** unless the viewer holds a specific
  permission to include drafts.

So if a transcript looks incomplete, the missing marks are probably still
drafts.

## 6.5 Tests

**LMS → Tests.** Online tests taken by enrolled students. (Entrance exams for
*prospective* students are a different feature — see
[chapter 2](02-leads.md) §2.9.)

### Building a test

1. **Create** it — name, instructions, how many minutes a student gets once
   they start, and the subject. Optionally tie it to a program and academic
   year.
2. **Add questions** — multiple-choice (with options and the correct answer) or
   short-answer. Each carries marks; the total is calculated for you.
3. **Publish** it.
4. **Map** it to students, setting the window during which they may take it —
   the earliest start and the latest submission.

### Students taking it

Students take the test from their portal. The clock starts when they start, and
runs for the duration you set, within the window you allowed.

### Results

- **Multiple-choice answers are marked automatically.**
- **Short answers wait for you** — open the attempt and score each one, with
  feedback if you wish.
- The test report shows how the group performed.

**Close** the test when the window has passed.

### Who can do what

You can always create and edit **your own** tests. Publishing, mapping,
reviewing, editing or deleting **someone else's** each need their own
permission.

## 6.6 What your actions affect

| When you… | This happens elsewhere |
|---|---|
| Publish an assignment | Students see it in the portal and receive an email |
| Publish a courseware topic | Only students in the batch **at that moment** get access |
| Get a lesson plan approved by both reviewers | Students can see it — on the display date if you set one |
| Publish marks | They appear in the student's transcript and portal; further edits need a permission |
| Publish and map a test | Students can take it during the window you set |
| Grade a submission | The student sees the mark and feedback in the portal |
